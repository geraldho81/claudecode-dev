What is Claude Code

Not a chatbot.
It actually does the work.

Claude Code runs in your terminal. It reads your actual files, understands your project structure, writes code, runs commands, and keeps going until the job is done.

You're not copying answers out of a chat window and pasting them into your editor. You describe what you want, and it does it — inside your project, on your machine.

Safety first

Plan Mode — see what
it'll do before it does it

Before Claude touches a single file, it tells you exactly what it plans to change. You read it, say yes, or tell it to do something different.

01

Propose

Claude reads the relevant files and drafts a plain-English execution plan listing every file it intends to change and why.

02

Review

You read the plan. Spot an approach you disagree with? Redirect it before any code is written. No rollback needed.

03

Execute

Once you approve, Claude works through the plan step-by-step. Each file change appears in your editor in real time.

Trigger Plan Mode anytime

Add "think through this step by step before making any changes" to your message. Or type /plan at the start. Use it any time you're about to touch something important — shared components, login flows, anything you'd be nervous about breaking.

Prompting well

The more detail
you give, the better it works

Claude Code does exactly what you ask. If you're vague, you get vague results. If you're specific, you get something that actually works.

WEAK PROMPT

"Add a login page"

Missing: stack, existing auth setup, component conventions, redirect behavior, error states.

STRONG PROMPT

"Add a /login route using our existing Next.js App Router setup. Use the AuthContext in src/context/auth.tsx. On success, redirect to /dashboard. On failure, show an inline error using the ErrorMessage component. Match the form styles in src/components/ui/Form.tsx. Do not touch the middleware.ts file."

The four elements

GOAL

What you want built or fixed, in one clear sentence.

CONTEXT

Which files matter. Which patterns to follow. Which libraries are already in use.

LIMITS

What not to change. Auth, shared utilities, public APIs — declare them off-limits explicitly.

SUCCESS CRITERIA

How you'll know it's done. "Tests pass", "No TypeScript errors", "Matches the Figma design".

Keeping it focused

Claude has a memory
limit. Use these commands.

Claude remembers your conversation, but only so much of it. The longer a session goes, the more it can drift. These three commands keep it on track.

/clear

Start fresh

Clears the whole conversation. Use this between separate tasks — don't let a debugging session carry over into a new feature.

/compact

Compress and keep going

Shrinks the conversation history to free up space, without losing what you were working on. Good when you're in the middle of something and don't want to start over.

Fresh session

When it stops making sense

If you've corrected it twice and it's still getting it wrong, stop. Open a new session and ask again more clearly. The problem is usually the conversation history, not Claude itself.

Project rules

Tell Claude how
your project works — once

CLAUDE.md is a plain text file you put in your project folder. Claude reads it every time it starts. Write your rules in there once and you never have to repeat yourself.

# Generate a starter CLAUDE.md

$ claude /init

Scanning project structure...

Detected: Next.js 14, TypeScript, Prisma

Writing CLAUDE.md...

Done. Review and customise before next session.

Run /init on a real project

Don't run it on an empty folder. Wait until you have actual files. Claude generates a much better starting point when it has code to read.

What to put in CLAUDE.md

STACK

Framework, language, test runner, CSS approach. Things Claude detects but shouldn't guess.

CONVENTIONS

Component naming, file structure, import style, whether you use default or named exports.

OFF-LIMITS

Files that should never be modified unless explicitly asked. Auth, payment, migration files.

WORKFLOW

Run tests before committing. Always create a branch. Never push to main directly.

Personal vs. project rules

~/.claude/CLAUDE.md — your personal rules that apply to every project. How you like your code formatted, things you never want it to do. Keep it short — one page is enough.

./CLAUDE.md — rules for a specific project. Commit this file to your repo so everyone on your team gets the same consistent behaviour.

Parallel work

Run multiple tasks
at the same time

Some features have parts that don't depend on each other. Claude can split those up and work on them at the same time — front end, back end, and tests all in parallel.

Example: new feature rollout

AGENT 1

Builds the API route and controller logic

AGENT 2

Builds the React UI components

AGENT 3

Writes tests for both ends simultaneously

MAIN AGENT

Coordinates, merges results, resolves conflicts

Pro and Max only

Subagents consume more tokens because multiple instances run concurrently. Available on Claude Pro and Max plans. Worth it for large feature work.

When to use subagents

→ Features with clearly separate frontend and backend work

→ Generating tests for multiple modules at once

→ Migrating multiple files to a new pattern simultaneously

→ Running code review and documentation in parallel

Working safely

Git is your
safety net

Claude Code is git-aware. It works within your repository, respects your branches, and can commit — but only when you tell it to. Your version control is the last line of defence.

Work in a branch

Always start on a feature branch. If Claude makes a change you don't like, git checkout . restores everything. No custom undo system needed.

Scope it to a folder

Claude Code only touches files in your working directory. It cannot reach outside your project. Your system files, other repos, and secrets outside the folder are unreachable.

Approve every change

Each file modification requires your approval. Read the diff before you accept. This is not an autopilot — it's a tool that proposes and you decide.

Checkpoints and rewind

Before any large change, Claude creates a checkpoint. If you don't like the result, press Esc twice or run /rewind to roll back to the last checkpoint. Think of it as a save state — not a replacement for git, but useful mid-session.

The honest truth

Where it can still
get things wrong

Claude Code is good. It's not perfect. Here's what it struggles with and what to do when it does.

Big structural decisions

Claude can build whatever structure you describe. But it can't decide what structure is right for your project and your team. That decision is still yours to make.

Making up library methods

For less common libraries, Claude sometimes confidently uses functions that don't actually exist. Always check the docs for any third-party package calls, and run your tests.

Forgetting rules mid-session

The longer a session runs, the more it starts to forget your earlier instructions. Use /compact every hour or so during a long working session to keep it on track.

Getting lost in big projects

If your project has a lot of files, don't let Claude scan everything at once. Tell it which folder or file to look at. The more specific you are, the better it works.

Login and payment code

Always read through any login, payment, or user data code that Claude writes. It'll work — but you need to check it's also secure. Don't ship it without reviewing.

Going in circles on a bug

If it tries the same fix three times and still can't solve it, stop. Start a new session, explain the bug more clearly, and give it a smaller, more focused task.

Troubleshooting

Common problems.
Quick fixes.

PROBLEM

Claude edits the wrong file

FIX

Name the exact file path in your prompt. Revert via git. Be explicit about scope with "only touch src/api/routes.ts".

PROBLEM

Tests pass but the feature is broken

FIX

Claude wrote tests that match its own code, not your intent. Add success criteria to your prompt: describe the user behaviour that should work, not just "tests pass".

PROBLEM

Claude keeps making the same mistake

FIX

After two failed corrections, the session context is the problem. Run /clear and restart with a cleaner, more constrained prompt.

PROBLEM

TypeScript errors after a change

FIX

Paste the full tsc output back into the session. Claude reads compiler errors well. If it still fails after two attempts, revert and try a smaller scope.

The landscape

Other tools worth
knowing

Claude Code is the best fit for most web developers. Here are the alternatives and when they make sense.

Cursor

IDE-first. Exceptional for autocomplete and inline edits inside VS Code. Less capable at autonomous multi-file tasks.

Best when: you prefer IDE integration over terminal

Aider

Open-source terminal agent. Similar philosophy to Claude Code. Supports multiple model backends. Lighter weight, less polished.

Best when: you want open-source and model flexibility

OpenAI Codex CLI

Cloud-based, asynchronous. You can queue tasks and walk away. Less interactive than Claude Code but good for long background jobs.

Best when: you want to run tasks and check back later
